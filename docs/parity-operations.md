# Operator commands, installed clients, and onboarding

Operators need to inspect policy sources, choose where data lives, run checks from a clean installation, and recover the same policy generation after a restart. Developers also need a way to connect their coding client and verify what it can actually do. These rows cover the Python entry points for those workflows and the work each requires in Java.

## Reading the matrix

Python paths use the pinned [Python tree](https://github.com/nnennandukwe/policyNIM/tree/fcc5322a6672b0275dcc6e0c299e631df8e8de19). In the authority column, module names refer to files under `src/policynim/` with the `.py` extension. Test names start with `test_` under `tests/` and use the same extension. Documentation and script paths start at the repository root. Java classes and package names refer to the pinned [Java tree](https://github.com/nnennandukwe/java-policyNIM/tree/d544829804891dda1f4e5d5e57f07146eed51342).

**Completion evidence for every row below is pending.** The two trees establish which commands and interfaces exist. Each proof cell names the missing observation. Record the tested, reviewed, and merged Java revisions, the command or client version, fixture identity, and result when closing a row. A source reference or a Python acceptance receipt alone can't close a Java row.
