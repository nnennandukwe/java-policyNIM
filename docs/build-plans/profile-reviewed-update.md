## Summary

An operator can review a policy pack diff before accepting changed source pins. Add `profile update PATH --expect-digest TOKEN [--format text|json]` to the installed Java jar. ## Scope

## Canonical Contracts

Update requires the exact review token from diff. It covers the original profile after universal newline decoding, one LF and the compact current model. A missing required option is usage exit 2. A stale token, invalid decision, final profile symlink or I/O refusal uses exit 1 and the existing error envelope. Check token before decision validity, decision validity before final symlink refusal. A verified no-change update can succeed. On success return exit 0 and `{"status":"ok","path":<caller spelling>,"diff":<reviewed report>}`. The ten diff fields retain their types and order, including `warnings`. Text names the profile whose pins were updated, says the index hasn't changed, prints each warning and directs the operator to profile preview. ## Component Design

**Source-aware edits.** Tomlj 2.2.0’s public parse result retains the input. `inputPositionOf`, `entry(List.of(key)).value().position()`, comment locations, table mutators and `toToml(TomlWriteOptions.defaults().withVersion(TomlVersion.V1_0_0))` cover structured selection and rendering. One-based line and Unicode code-point columns must be converted before indexing a Java string. With an astral character before a key, `offsetByCodePoints` locates the token. In a probe the revision table’s value starts at `{` for an inline assignment, `[` for a table header or the key for a dotted assignment. Use literal key lists for IDs containing dots, quotes, brackets, hash marks, equals signs or astral characters. Context7 returned no Tomlj match. The exact release documentation, compiled artifact and JDK 21 probes establish this API. [Public editor](https://github.com/tomlj/tomlj/blob/80c0ce8bcd12fcdb7c13aba6087a33dc3c0081e9/docs/editing.md) · [Layout and versioned writing](https://github.com/tomlj/tomlj/blob/80c0ce8bcd12fcdb7c13aba6087a33dc3c0081e9/docs/writing.md)

Visit each pack in its declared order. Edit `path`, `version`, `digest` and individual `policies` pins. Preserve operator comments, decision records, key spellings and layout. The pinned editor reassigns every pack's path, version, digest and policy-revision string. Even a semantically unchanged single-quoted path becomes a double-quoted basic string. Limit that rendering to those assigned value tokens. A change in the source's newline convention can also affect every line of the published file. For removal from a normal table, emit the removed policy and old digest as a TOML comment using Python’s ASCII JSON string spelling, then preserve the original trailing note as a separate comment. For an inline revision table remove the entry and adjust its delimiter. The Tomlj probe retained all policy values and operator notes in both independent fixtures. Its default renderer inserted three blank lines and removed one space around the normal removal comments. In the inline fixture it moved one space from after the comma to before the closing brace. Both differences changed the artifact hash. Use parser-anchored edits of the affected value, revision-entry or delimiter spans to meet the exact fixture outputs. Leave untouched spans verbatim, including a comment attached to the next entry. Render new key/value literals through the TOML 1.0 writer. Guard any splice against the original source and reparse through `ProfileToml` for full typed equality with the reviewed model before publication. Test paths and reasons containing control characters valid in TOML strings. [Reference editor](https://github.com/nnennandukwe/policyNIM/blob/fcc5322a6672b0275dcc6e0c299e631df8e8de19/src/policynim/services/profiles.py#L607-L644)

The installed reference diff accepted a pack whose revisions used separate dotted assignments for A and B. Update of that layout exited 1 with `Pack policy revisions must form a TOML table.` The pinned implementation checks the TOML editor item type returned for the revisions and tomlkit 0.14.0 returns a proxy for that layout. Test the observed refusal, unchanged original bytes and a successful retry after rewriting those assignments as a normal revision table and obtaining a fresh diff. A single dotted revision assignment and explicit inline revision tables succeeded. Keep those supported cases. [Pinned update check](https://github.com/nnennandukwe/policyNIM/blob/fcc5322a6672b0275dcc6e0c299e631df8e8de19/src/policynim/services/profiles.py#L616-L625)

**Cooperating writers.** Acquire an exclusive lock on `.<profile-name>.lock` before the first diff. Keep its handle open through replacement, parent sync and cleanup. Leave the lock file on disk. Lock release follows descriptor closure or process exit. POSIX opens a regular file with create/read-write, no-follow and nonblocking flags where supported, mode 0600 on creation. Use native `flock` on this handle. A private macOS process check found JNR 3.2.8 returned `EWOULDBLOCK` while Python held the lock and succeeded after release. On Linux local filesystems, OpenJDK’s Unix `FileChannel.lock()` uses `fcntl`, which can't coordinate with Python’s `flock`. On Windows, select an exclusive one-byte range at offset zero, as CPython does. JDK 21’s `FileChannel.lock(0,1,false)` uses `LockFileEx`; qualify it against the Python writer and regular handle on Windows. Propagate fatal errors and cancellation. If using nonblocking attempts, retry only contention. [Reference lock](https://github.com/nnennandukwe/policyNIM/blob/fcc5322a6672b0275dcc6e0c299e631df8e8de19/src/policynim/storage/file_lock.py#L14-L61) · [JDK Unix](https://github.com/openjdk/jdk21u/blob/jdk-21.0.10-ga/src/java.base/unix/native/libnio/ch/UnixFileDispatcherImpl.c#L190-L218) · [Linux manual](https://man7.org/linux/man-pages/man2/flock.2.html) · [JDK Windows](https://github.com/openjdk/jdk21u/blob/jdk-21.0.10-ga/src/java.base/windows/native/libnio/ch/FileDispatcherImpl.c#L396-L418)

**Stage and commit.** Under the lock, validate token, decisions and final file type. Reread the original file through a regular-file descriptor and get its POSIX access bits from that same handle. Compare its decoded text with the reviewed capture. Create a private sibling staging directory and file, record their filesystem identities, write UTF-8, flush, apply low nine mode bits to the opened staged file on POSIX, force it and close it. Rerun a complete diff against the selected sources. Require matching original text and digest, and matching owned stage file and directory immediately before replacement. Use a directory-relative atomic rename on POSIX with a retained directory descriptor, such as libc `renameat` through the shipped JNR FFI. Compare device and inode at the handle and directory-entry boundary. On Windows, reuse init’s held file and directory handles for a same-volume rename with replacement enabled. Check that the existing file belongs to the reviewed transaction and that a fresh reader can open the replacement on the native runner. Where the provider lacks the required atomic move, report a precommit failure. The destination name changes at successful replace. POSIX then syncs its parent directory. Windows promises atomic visibility. [Reference transaction](https://github.com/nnennandukwe/policyNIM/blob/fcc5322a6672b0275dcc6e0c299e631df8e8de19/src/policynim/services/profiles.py#L475-L582) · [Java directory-relative operations](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/nio/file/SecureDirectoryStream.html) · [Windows JDK move](https://github.com/openjdk/jdk21u/blob/jdk-21.0.10-ga/src/java.base/windows/classes/sun/nio/fs/WindowsFileCopy.java#L295-L324)

The installed reference CLI returns the original reviewed diff after a successful update. Replaying an old changed-source token fails. Reusing a current clean token succeeds without changing the profile bytes. A usage error for a missing required option creates no lock. Once a valid command starts, a missing profile under an existing parent can leave the cooperating-writer lock. Check these outcomes from outside the checkout. ## Failure And Recovery Rules

Clean up only the stage file and directory whose identities match those created by this invocation. Release handles on every exit. A precommit exception remains the primary error if cleanup also fails. A postcommit failure must keep the published profile and identify what the operator should do. Emit the following exact phrases in the reviewed diff’s warnings, in order when both apply. [Postcommit code](https://github.com/nnennandukwe/policyNIM/blob/fcc5322a6672b0275dcc6e0c299e631df8e8de19/src/policynim/services/profiles.py#L540-L573) · [Pinned CLI acceptance](https://github.com/nnennandukwe/policyNIM/blob/fcc5322a6672b0275dcc6e0c299e631df8e8de19/tests/test_policy_profiles.py#L1241-L1303)

1. `Profile pins changed, but directory sync failed. Reread the profile before retrying or restarting.`
2. `Profile staging cleanup couldn't finish. Preserve unexpected entries and inspect the profile before retrying.`

The second read checks source changes visible at that point. Cooperating writers serialize through the lock. External editors must finish their changes before update because the filesystem can't atomically compare multiple independent pack directories and the profile. A hard process exit can leave a private stage. State which side of replacement the test observed and use ordinary preview/diff for recovery. Test controlled interruption separately from process termination. ## Definition Of Done

Each installed client can update a file reviewed by the other. A second writer observes the first commit before validation. Refusals preserve the prior profile or the operator’s new edit. A subsequent read proves which pins were published. Source formatting, composed profile identity, report schema and expected warning outcomes pass the agreed fixtures and exact-head gates.

## Assumptions And Defaults

This unit targets trusted local profile directories on the three native CI platforms. Shared or network filesystems can differ in lock and durability behavior. No new provider, credentials, services, release or deployment are needed.
