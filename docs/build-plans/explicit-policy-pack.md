# Explicit policy pack inspection Build Plan

## Summary

A pack author uses `pack.toml` to select policy files and record who wrote or adapted each policy. This build lets an operator inspect that selection, its original source revisions and its declared authority through the installed Java catalog commands. A manifest error reports the affected field or member before the command returns any catalog.

## Component Design

Keep `SourceCatalog.read(Path)` as the caller's only catalog entry point. Have its directory owner check for `pack.toml` once at the canonical root, including a dangling link. Let the plain branch continue through `PlainSourceDirectory.forEachFile`. A proposed package-private `PolicyPackManifest` holds typed declarations and source metadata. A pack reader returns a named member's captured bytes and resolved relative path for canonical uniqueness. Use the normalized lexical name for the parser and catalog. A unique alias retains its authored name in public identity.

Call the same UTF-8 decoder, Markdown parser, effective-ID conflict check and entry assembler from both branches. A strict parser overload reports unknown top-level keys while retaining the existing body and rule parser. Pass typed provenance into `CatalogJson.entry` where the plain branch supplies its established unknown values. Hash the same bytes that the parser read. Gather unlisted paths by listing directory entries without opening their contents or following directory symlinks. Reuse the code-point comparator for output ordering. [Python loader](https://github.com/nnennandukwe/policyNIM/blob/fcc5322a6672b0275dcc6e0c299e631df8e8de19/src/policynim/ingest/loader.py#L33) · [Command presentation](https://github.com/nnennandukwe/policyNIM/blob/fcc5322a6672b0275dcc6e0c299e631df8e8de19/src/policynim/interfaces/cli.py#L161)

The POSIX reader opens the selected canonical root with `O_DIRECTORY|O_NOFOLLOW`, resolves an in-root alias and opens each canonical component relative to the retained directory descriptor. Intermediate components require `O_DIRECTORY|O_NOFOLLOW`. The last component requires `O_NOFOLLOW|O_NONBLOCK` and an opened regular-file check before reading. Use close-on-exec where supported. Handle short reads, EOF, interruption and every error exit. Never reopen the member by its pathname after checking its descriptor. On Windows, perform the final-path and file-type checks before the first byte read on the open handle. This binds each member's bytes independently. The operator can still change a different member during inspection.

## Failure And Recovery Rules

Malformed TOML, invalid UTF-8 in a selected file, a schema error, an invalid member, an ID mismatch or a strict metadata violation returns the existing source failure envelope and exit code 1. Use a dotted field location where the reference supplies one, including `policies.0.sources.0.url`. Keep raw inputs, Java exceptions and partial policy results out of public errors. An unreadable manifest fails the pack selection. An unlisted binary notice passes source inspection. The next invocation reads a corrected source afresh.

Probe both models on integers outside signed 64-bit range. Python parses the integers, then rejects the two tested values during validation at `schema_version` and `policies.0.sources.0.retrieved_on`. Tomlj rejects them during parsing. Preserve the source error, exit status and safe field information at the CLI boundary. Verify the actual messages before recording diagnostic parity. Tomlj can also represent the native calendar year 0, which Python’s TOML reader rejects. Check the native year of each date and datetime before coercion or catalog publication.

Use deterministic filesystem fixtures to check that the regular file read belongs to the selected root or that the command returns a controlled refusal. Cover valid unique in-root aliases to files and directories, duplicate canonical names, dangling members, a changed root and a nonregular final member. Confirm successful reinspection after restoring the fixture. Give nonregular-file cases a process deadline. Exercise Windows final-path validation and handle release on a real Windows filesystem. Exercise descriptor-relative reads on macOS and Linux.

## Assumptions And Defaults

An operator supplies the pack locally. Each declared URL remains metadata throughout inspection. The process doesn't contact source publishers. Requirement level, grounding, attribution, sections and change notices are the pack author's declarations. Inspection doesn't certify compliance with a standard. The planning probe ran on arm64 macOS with the candidate JNR dependencies on a flat classpath. Windows and Linux native reads and the repackaged jar on every target still need process evidence.
